# Code review

Inputs: the diff of **one task** (or branch), `specs/<slug>/06-feature-spec.md` and `07-tasks.md` if they exist. Read `docs/01-workflow/definition-of-done.md`. Do not modify code during review; report findings. For tier M and L, also append the result as a round entry in `specs/<slug>/08-review-log.md` (`docs/templates/review-log.md`): that file is a document, not code, and is the record of the PR gate.

## Review passes

1. **Grounding.** Does the PR list `Docs consulted`? Spot-check 2 to 3 library calls against installed version and official docs (use `verify-library-docs`). Flag any API that looks remembered rather than verified (removed or renamed APIs, old package names, v3/v4-era idioms). Zero deprecated API usage: `lint` catches a call marked `@deprecated` in the installed types; also read the `test` and `build` output the PR reports for a deprecation warning printed at run time, and check that a new library call is not marked deprecated in its docs for the installed version.
2. **Architecture and design.** Apply `docs/02-architecture/design-principles.md`: any new interface or abstraction has two real uses or a stated test seam; no unit with two reasons to change; complexity limits (`design-principles.md`); narrow props; vendor SDKs not imported in services. Code in the right feature; routes thin; no deep cross-feature imports; no service function exported from `index.ts`; UI and routes never import `index.server.ts`; events are defined by their owner, published after the change is saved, and handlers never fail the publisher; `shared` has no feature imports; no Drizzle outside repositories; DTOs not rows; a `*.rules.ts` file is pure: no package that does I/O, `node:` module, clock, or random value (lint cannot see these; ADR 0013), and a large rule is not buried in a service.
3. **Server functions and routes.** Validated with Zod (schema traps in `docs/04-stack/zod.md`: `.trim()` before `.min()`, no `.partial()` over defaults); authorization inside function/middleware; correct HTTP method; allow-listed sort/filter; cache headers safe; tenant scoping; no server function calling another to reuse logic; a server function (`*.functions.ts`) imported statically, never with `await import()` (lint rejects a literal path; check a path built at run time: `docs/04-stack/tanstack-start.md`, rule 2); server routes use the response helpers and status table in `api-conventions.md`; `src/start.ts` keeps the CSRF middleware; a route called by our own UI declares its own, and a webhook or public route does not; every route under `src/routes/api/**` authenticates its own requests, because no function middleware runs there (ADR 0012). Auth config against `docs/04-stack/better-auth.md`: `tanstackStartCookies()` last; no `disableCSRFCheck` or `disableOriginCheck`; `trustedOrigins` minimal, with no wildcard; a plugin or sign-in method beyond email and password has its ADR (a skill being installed is not adoption); secret and URL through the env module; auth tables from the CLI, then a generated migration. Anything taken from a Better Auth skill follows `docs/05-agent-tooling/skills.md`, not the skill's samples.
4. **Data.** Migration generated and reviewed against `docs/03-standards/database.md`, no destructive surprises, `drizzle-kit check` clean, no merged migration folder changed or deleted, no `relations.ts` or `schema.ts` left in `drizzle/` by `pull`, indexes, explicit `onDelete`, no `CASCADE` and no query across features, a cross-feature FK choice recorded in the spec, transactions for multi-writes, constraints tested; ownership in the `WHERE`, named columns, a limit on every list. In a transaction: every query uses `tx`, never `db`; an expected failure after a write rolls back (a returned `Result` commits); no caught query failure followed by more statements without a nested transaction. Concurrency: each collision point the spec (section 4, "Transactions and concurrency") assigns to this task has its mechanism in code (a constraint, a condition in the write, an optimistic lock on `version`, a row lock with `.for('update')` or `.for('share')` on `tx`, or an idempotency key: `docs/04-stack/drizzle-concurrency.md`), and a test runs the colliding writes together against a real database and checks the stored data. A read in the service whose answer decides a later write, with no lock and no condition in the write, is a race (check-then-write), including a status check inside a transaction without `.for('update')`; a save of an edit form with no `version` is a lost update; a version conflict the UI retries on its own is a lost update too. Fetching follows `docs/02-architecture/data-fetching.md`: a query whose server function joins another feature's data declares `meta.dependsOn`, and mutation hooks invalidate with `invalidateFeature` (`tanstack-query.md`, rule 12); no server route just for our own UI, queries on a page start in the loader, nothing sensitive in `GET` input.
5. **TypeScript and suppression.** Zero suppressions: no `any`, `!`, narrowing `as`, `as unknown as`, `@ts-*`, `eslint-disable`, `.only`/`.skip`, coverage ignores. Check the diff of `eslint.config.js`, `eslint.ai-docs.js`, `eslint.boundaries.js`, `eslint.code-rules.js`, `eslint.no-suppress.js`, `tsconfig*.json`, `scripts/check-*.mjs`, CI, and `package.json` scripts: any weakening is blocking. Boundaries validated; exhaustive unions.
6. **State and UI.** Each value in the right home (`docs/02-architecture/state-management.md`); server state only in Query; optimistic hooks roll back on a thrown error and on `ok: false`; shared `queryOptions` between loader and component; forms share the server's schema; one mapper for form defaults and reset, reactive logic in field `listeners`, sections with no state of their own (`docs/04-stack/tanstack-form.md`); interactive tabular data uses `useTable` (`docs/04-stack/tanstack-table.md`); component size, narrow props, primitives reused, render body safe for SSR (`docs/03-standards/components.md`); conditional classes through `cn()`, mobile-first classes; every change to `shadcn-primitives.lock.json` read: a new `reason` must be a listed lint fix or an approved generic variant, and a new `own` entry must be our code, otherwise blocking (`docs/04-stack/tailwind-shadcn.md`); loading/empty/error states; accessibility basics.
7. **Errors and logging.** expected failures are a `Result` with an `AppError` (code in the feature's `errors.ts`, text in the UI map), unexpected ones go through `withErrorBoundary`; mutations and forms branch on `data.ok`; no class, no `instanceof` on our errors; no swallowed errors, no leaked internals, no secrets/PII in logs; caught errors logged under pino's `err` key.
8. **Tests and traceability.** The PR lists the acceptance criteria it covers and each has a test; for logic and bug fixes there is test-first evidence (a failing run for the right reason); failure paths covered; real DB for persistence; regression test for fixes; commands actually run. The change stays within its task in `07-tasks.md`: every changed file is in the task's file list, or the change log in `07-tasks.md` says why not.
9. **Hygiene.** Naming and comments follow `docs/03-standards/conventions.md`: each collision point has its `Race:` comment, and a follow-up `TODO` names a task or issue; the smells in `docs/02-architecture/design-principles.md`, "Smells to flag in review", are flagged with their remedy; displayed dates and numbers go through `shared/lib/format.ts` (`docs/03-standards/components.md`); artifact and PR text follows `docs/03-standards/writing.md`; business knowledge has one owner, not a copy (`coding-standards.md`); new dependencies have an ADR; env vars in `.env.example` and schema; docs updated; commit messages conventional. Read for what lint passes: `docs/03-standards/linting-and-formatting.md`, "What the gates do not catch".

## Output format

```
Verdict: approve | request changes | blocked (needs human decision)

Blocking
- [file:line] <issue> — <why it matters> — <suggested fix>
Non-blocking
- [file:line] <suggestion>
Unverified
- <claims/APIs the reviewer could not verify>
Checked and fine
- <short list, so the author knows what was examined>
```

Severity rules: security, data loss (a race included), auth gaps, hallucinated, removed, or deprecated APIs, boundary violations, and any suppression or weakened gate are always **blocking**.
